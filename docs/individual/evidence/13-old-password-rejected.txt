After rotating the PostgreSQL role password and updating the secret, the old
password was tested directly with psql on the app instance:

$ PGPASSWORD='<old password>' psql -X -w -h db.timecapsule.internal \
    -U timecapsule -d timecapsule -c 'SELECT 1'
psql: error: connection to server at "db.timecapsule.internal" (10.18.10.73),
port 5432 failed: FATAL: password authentication failed for user "timecapsule"

The new password is read by the application from Secrets Manager; the old
value is not present in the new AMI or .env. The old AMI snapshots still
contain the old string, but it no longer grants access to the database.
