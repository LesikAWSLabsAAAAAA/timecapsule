# ADR-0004. Размещение PostgreSQL для TimeCapsule

## Статус: принято

Решение реализовано в ЛР5 и заменяет [ADR-0002](0002-database-placement.md).

## Контекст

В ЛР3 PostgreSQL работает на отдельном EC2 в приватной подсети. Для TimeCapsule нужны регулярные резервные копии и восстановление на выбранный момент, но учебная среда не требует круглосуточной доступности.

## Решение

Перенести PostgreSQL 16 в Amazon RDS Single-AZ (`eu-central-1a`), `db.t4g.micro`, 20 ГиБ gp3 без автоподращивания. Экземпляр без публичного доступа; TCP 5432 разрешён от SG сервера приложения, хранилище зашифровано, включена защита от удаления. Приложение подключается по TLS отдельной ролью `timecapsule`. После переноса данных `db.timecapsule.internal` станет CNAME на DNS-имя RDS.

## Рассмотренные альтернативы

| Вариант | Преимущество | Почему не выбран |
| --- | --- | --- |
| PostgreSQL на EC2 | Полный контроль ОС и СУБД | Нужно самим обновлять сервер, настраивать резервное копирование и проверять восстановление. |
| RDS Single-AZ | Управляемое обслуживание и PITR при минимальном учебном бюджете | Выбран; простои при обслуживании и отказе зоны допустимы. |
| RDS Multi-AZ, DB instance | Синхронный standby в другой зоне и автоматический failover | Дополнительный экземпляр и хранилище повышают стоимость; standby этого варианта не обслуживает чтение. |
| Amazon Aurora PostgreSQL | Распределённое хранилище и возможность переключиться на другую зону при наличии реплики | Дополнительные возможности не нужны для учебной нагрузки; стоимость зависит от конфигурации вычислений, хранения и I/O. |

## Последствия

- **Данные.** При включённых автоматических копиях RDS делает ежедневную резервную копию и выгружает журналы транзакций примерно каждые пять минут для PITR. В конфигурации Free запрошен 1 день хранения вместо 7 дней из задания. При аварии записи после `LatestRestorableTime` могут не восстановиться: примерно пять минут — ориентир, не гарантия. После остановки следует проверять фактическую границу доступного восстановления.
- **Стоимость.** По смете задания около $13–14 за три месяца при трёх часах работы в день (`eu-central-1`). Хранилище оплачивается и при остановке. RDS автоматически запускается не позднее чем через семь дней; Scheduler в 23:00 `Europe/Chisinau` остановит уже доступную базу при очередном успешном вызове. Автоматического утреннего старта нет.
- **Доступность.** Две подсети в subnet group не делают экземпляр Multi-AZ. При отказе `eu-central-1a` автоматического переключения нет: при необходимости восстанавливаем новый экземпляр в доступной зоне и обновляем CNAME. Основной сервер приложения также находится в `eu-central-1a`; для восстановления всего сервиса нужен и доступный сервер приложения.
