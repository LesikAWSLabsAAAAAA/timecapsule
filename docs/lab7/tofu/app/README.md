# ЛР7: инфраструктура приложения

Самостоятельный стек, существующие VPC, приватные подсети, RDS, её SG и IAM-роль
приложения читаются по именам ЛР5/6. К RDS SG добавляется отдельное правило,
к существующей IAM-роли — отдельная inline policy; другие ресурсы не импортируются.
Проверьте plan на конфликты имён и изменение правил SG: ЛР5 также управляет
inline ingress этой SG, поэтому возможен конфликт между состояниями.

Обязательные inputs: `mailer_zip`, `opener_zip` — пути к внешним zip для
Python 3.13 x86_64 (handler.py, зависимости и CA bundle); `db_user`,
`db_password`, `email`. Опциональные: `region` (eu-central-1), `db_name`
(timecapsule), `db_sslrootcert` (/var/task/global-bundle.pem),
`enable_mail_trigger` (false), `enable_scheduler` (false),
`schedule_expression` (rate(1 minute), UTC). Используйте RDS CA bundle,
подходящий региону и сертификату; hostname берётся непосредственно у RDS,
чтобы работала проверка verify-full. Обе функции должны иметь доступ к БД.

Пароль и email помечены sensitive, но **сохраняются в состоянии и планах**;
пароль также передаётся в конфигурацию среды Lambda. Защитите state, планы и
доступ к Lambda; не сохраняйте значения в репозитории. Для production
предпочтительны Secrets Manager и изменение кода для получения секрета.
AWS managed `AWSLambdaVPCAccessExecutionRole` включает широкие EC2 ENI и
CloudWatch разрешения; рассмотрите ограничение ENI-действий из кода функции.

Для включения необходимо проверить развёртывание новой версии PHP, установить
индекс mailer после проверки дубликатов, подтвердить email-подписку,
проверить работающую RDS, TLS и совместимость архивов. Максимальная
конкурентность mailer ограничена значением 2 на уровне event source mapping:
резервирование конкурентности Lambda недоступно при квоте этого аккаунта.
Email получает только
успешные результаты opener с `responsePayload.eventType=capsules.opened`;
mailer имитирует письмо и не отправляет его. Очередь хранит ошибки в DLQ,
но SNS-доставка в очередь и async destination не имеют отдельных DLQ/alarms.
Доставка событий не является exactly-once, а транзакция opener и SNS не
атомарны. При остановленной RDS вызовы завершатся ошибкой.

Пакеты можно пересобрать командой `bash ../../lambdas/build.sh` из этого
каталога; путь каждого ZIP передаётся в `mailer_zip` или `opener_zip`.
На EC2 необходимо задать `EVENTS_TOPIC_ARN` равным выходу `topic_arn`;
пустое значение в примере `.env.example` намеренно не является рабочим.
Новая версия PHP больше не открывает капсулы при запросах: для работы
необходимо включить расписание, а для обработки писем — SQS mapping.
Включайте их только после запуска RDS и готовности сетевого доступа. В конце
занятия верните `enable_mail_trigger` и `enable_scheduler` в `false`.
После остановки bastion его автоматически назначенный публичный IP может
смениться; `~/.ssh/config` нужно обновить после следующего запуска.

Выходы: ARN темы, URL/ARN очереди, URL DLQ, ARN функций, UUID mapping и имя
расписания. Scheduler и обработчик очереди по умолчанию отключены.
