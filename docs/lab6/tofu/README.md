# OpenTofu: ЛР6

Все каталоги независимы и используют локальный state. State и переменные могут содержать чувствительные сведения: не публиковать их и не удалять, пока соответствующие ресурсы существуют. Выполнять команды из нужного каталога; AWS-профиль должен указывать на нужный аккаунт.

1. `part1`: `tofu init`, `tofu apply`, затем после испытания `tofu destroy`. Стек ищет VPC, public-a/public-b и bastion по именам из ЛР3.
2. `sessions`: `tofu init`, `tofu apply`. Таблица и IAM-политика сохраняются после работы.
3. Обновить приложение на существующем `timecapsule-dev-app`, проверить работу сессий и только затем выполнить `tofu init`, `tofu apply` в `image`. AMI содержит файловую систему и `.env`; хранить его приватно.
4. В `app`: `tofu init`, `tofu apply -var='run_fleet=true'`. Для завершения — `tofu apply -var='run_fleet=false'`: это удаляет ASG и ALB, но оставляет target group, шаблон и группы безопасности. Это не остановит RDS, bastion или исходный app-server: их состояние проверяется отдельно.

В файлах указан существующий ключ `nitrokey` и роль приложения из ЛР3–ЛР5. Перед повторением в другом окружении имена нужно изменить. После опыта надо убедиться, что временные EC2 и ALB удалены: запущенные ресурсы тарифицируются.
